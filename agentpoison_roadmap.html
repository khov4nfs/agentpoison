Kế hoạch chi tiết

Phase 1 Tuần 1–2
day 1 Public repo flag-planting làm ngay
Tạo repo public, push commit đầu tiên dù chỉ là README.md với tagline + "coming soon". Mục tiêu: cắm cờ sớm để Google index trước nếu có ai đang nghĩ tới idea tương tự.
arena/core Arena runner
CLI nhận 2 agent config, orchestrate conversation loop, log toàn bộ interaction ra JSON. Chỉ cần chạy được, chưa cần đẹp.
arena/detect Attack success detector
Rule-based: blue agent có gọi tool ngoài scope không? Đọc file ngoài project dir không? Exfiltrate string ra ngoài không? Flag ngay khi phát hiện.
Phase 2 Tuần 3–4
agents/red 5 red agent đầu tiên ưu tiên cao
Mỗi agent là 1 YAML file định nghĩa personality + attack chain. Build theo thứ tự demo-first:
trust_builder → memory_poisoner → tool_hijacker → mcp_impersonator → salami_slicer
Bắt đầu với trust_builder: dễ demo nhất, hit đúng tâm lý "nó tin từng bước nhỏ, đến lúc blue agent nhận ra thì đã muộn". Giữ salami_slicer cho sau vì phức tạp hơn.
agents/blue Blue agent adapters
Wrapper cho Claude Code, OpenAI Agents SDK, LangChain. Mỗi adapter ~50 dòng TypeScript, chuẩn hoá interface.
Phase 3 Tuần 5–6
viral asset Demo video make-or-break <90s
TypeScript + ink để có terminal UI đẹp mà không cần web. Dùng asciinema record rồi convert sang GIF. Clip dưới 90 giây, không voice-over, chỉ có attack xảy ra và bị flag realtime.
acceptance Demo acceptance criteria
Người xem phải hiểu trong 10 giây đầu: red agent đang tạo niềm tin, blue agent làm theo, detector flag ngay khi boundary bị vượt. Nếu video không tự giải thích được khi mute, chưa đạt launch quality.
docs/ Attack taxonomy
Markdown docs mô tả từng attack vector với example thật. Đây là "content moat" — người ta cite, share, link tới. Quan trọng không kém code.
Phase 4 Tuần 7–8
launch README + launch sequence
README aggressive theo formula đã phân tích: GIF trước, fear-driven problem, 1-line install, holy-shit examples. Post HN + X cùng ngày, không split.
optional Web replay viewer
Nếu còn thời gian: upload JSON log → xem replay attack trên browser. Không bắt buộc cho v1 nhưng giúp share-ability tăng mạnh.

Quy tắc solo dev để không burn out

Không build feature nào không trực tiếp phục vụ demo video. Mọi thứ khác là backlog.
Ngày đầu phải có repo public + commit đầu tiên. Sau đó commit nhỏ mỗi ngày để tạo momentum và proof-of-work.
Post dev log ngắn trên X mỗi tuần — "đang build X, gặp vấn đề Y" — build audience trước launch.
Thứ tự ưu tiên tuyệt đối: demo dưới 90 giây > docs > code quality > features.
